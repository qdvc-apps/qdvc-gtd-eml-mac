### 2. Dropping onto a hashtag mailbox

I went with the "not allowed" pointer rather than an error message. Apple's HIG lists that pointer for exactly this case, and its guidance generally prefers preventing a mistake to reporting it with an alert. Because a pointer alone doesn't say *why*, the window subtitle also explains while you hover, for example "Cannot set the next action to #urgent. It already has a next action: "Waiting for Bob"". Accepted drops highlight the mailbox and show the green "+".

A few details:

- **Multiple emails:** if some of the dragged emails have a next action and some don't, the drop applies to the blank ones. The others are listed afterwards, the same way a partly refused move already works.
- **Emails in Input:** these are refused too, as the app already does for annotations.
- **Safe write:** the blank check re-reads `metadata.csv` just before writing, so a next action set by the CLI in the meantime is never overwritten.
- **Folders:** these now use the same hover check. Dragging onto a folder the move would be refused for (or the email's own folder) shows the same pointer and reason, instead of failing after the drop.

To make the hover check possible, dragging from the list now records which rows are being dragged when the drag starts. That means the existing drag-to-folder code was rewritten as well, so please re-test it.
